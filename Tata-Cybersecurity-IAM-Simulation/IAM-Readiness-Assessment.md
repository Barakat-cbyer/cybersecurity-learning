# IAM Readiness Assessment

## Task Overview

In this task, I reviewed the IAM readiness of TechCorp Enterprises, a fictional global technology company with more than 150,000 employees operating across over 100 countries.

The purpose of the assessment was to identify the areas that should be reviewed before improving or implementing an Identity and Access Management solution.

## Key Areas I Assessed

I considered the following areas:

- User lifecycle management
- Access control
- Authentication
- Privileged access
- Access reviews
- Compliance and governance
- Integration with existing systems
- Cloud integration
- Automation
- Logging and monitoring
- User experience
- Scalability

## Key Risks Identified

Some of the main IAM risks I learned to consider include:

- Former employees retaining active accounts
- Users having more permissions than they need
- Access not being updated when employees change roles
- Weak authentication controls
- Privileged accounts not being properly monitored
- Manual account management causing delays or errors
- Difficulty managing identities across cloud and existing systems

## My Approach

I used TechCorp's business size, global presence, digital transformation goals, and security concerns to determine what should be included in an IAM readiness assessment.

The assessment focused on whether TechCorp could securely manage identities while also improving operational efficiency and user experience.

## What I Learned

This task helped me understand that IAM implementation starts with understanding the organisation before choosing security technologies.

I learned that cybersecurity teams need to understand:

- Who the users are
- What systems they need access to
- What permissions they require
- How access is granted and removed
- How access activities are monitored
- How IAM supports the organisation's business goals

I also learned that poor identity management can create security risks such as excessive privileges, inactive accounts, and unauthorised access.

## SOC Relevance

IAM information can be useful during SOC investigations.

For example, suspicious login attempts, privilege changes, unusual account activity, and unauthorised access can all indicate a possible security incident.

Understanding normal user access makes it easier to recognise abnormal or suspicious behaviour.
